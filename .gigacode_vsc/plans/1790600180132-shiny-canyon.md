## Список проблем и решений

### 1. create_superuser.py → async URL в sync engine (КРИТИЧНО)
**Проблема:** `create_engine("postgresql+asyncpg://...")` → ошибка подключения
**Решение:** Использовать `create_superuser_sync.py` (уже существует в репозитории)

### 2. Alembic не получает DATABASE_URL (КРИТИЧНО)
**Проблема:** `alembic.ini` читает `${DATABASE_URL}`, но переменная не экспортирована в shell
**Решение:** Жёстко прописать psycopg2 URL в `alembic.ini`

### 3. Миграция countries.name_ru — nullable=False на пустой таблице (КРИТИЧНО)
**Проблема:** `ALTER COLUMN ... SET NOT NULL` падает если таблица пуста
**Решение:** Убрать `nullable=False`, добавить `server_default=''`

### 4. deploy.yml не обновляет systemd service (СРЕДНЕ)
**Проблема:** systemd service не имеет `Environment=DATABASE_URL=...`
**Решение:** Записать service file в deploy.yml

### 5. Логирование для отладки (УДОБНО)
**Решение:** Настроить SSH-туннель для tail логов

## Почему superuser "слетал" — полный анализ

1. **deploy.yml** вызывал `create_superuser.py`
2. `create_superuser.py` делал `create_engine(DATABASE_URL)` где `DATABASE_URL` = `${DATABASE_URL}`
3. `${DATABASE_URL}` не был экспортирован в shell → пустая строка → ошибка
4. Даже если бы был экспортирован — `postgresql+asyncpg://` не работает с синхронным `create_engine`
5. **Результат:** суперпользователь не создавался/не обновлялся при деплое

**create_superuser_sync.py** — это исправленная версия, которая:
- Содержит жёстко прописанный psycopg2 URL
- Определяет все модели локально (не импортирует из app.database)
- Работает без переменных окружения

**Почему он не используется в deploy.yml:** deploy.yml вызывал `create_superuser.py` вместо `create_superuser_sync.py`.
