# Fix Database Synchronization on Deploy

## Problem Analysis

Found 5 critical issues preventing proper DB sync during deployment:

### Issue 1: Broken migration chain (CRITICAL)
**File:** `online-booking/backend/alembic/versions/sync_missing_columns.py`
- `down_revision = 'aaa7fcc30d47'` — this SKIPS migration `f43f84fe3057` (timezone fixes + cleanup)
- On deployment, `alembic upgrade head` never applies the timezone migration
- Current (broken) chain: `9a9c2edb119f → 08fbbef38349 → aaa7fcc30d47 → sync_missing_columns`
- `f43f84fe3057` is ORPHANED between `08fbbef38349` and `aaa7fcc30d47`

### Issue 2: Missing `cities.name_en` column
- `City` model has `name_en` column but no migration adds it
- Will cause errors when app tries to query this field

### Issue 3: Hardcoded DATABASE_URL in `alembic.ini`
- `alembic.ini` has hardcoded URL: `postgresql+psycopg2://specialist:Postgres2024!Secure@localhost:5432/online_booking`
- Migrations don't use the `DATABASE_URL` environment variable passed by deploy.yml
- If DB credentials change, migrations break

### Issue 4: `create_superuser_sync.py` has hardcoded URL
- Same problem — hardcoded `postgresql+psycopg2://specialist:Postgres2024!Secure@localhost:5432/online_booking`
- Doesn't respect `DATABASE_URL` env var

### Issue 5: Empty initial migration
- `9a9c2edb119f_initial_schema.py` is empty (tables created manually via `Base.metadata.create_all()`)
- Alembic has no record of initial schema — `autogenerate` won't work properly
- Need baseline migration to capture current state

## Implementation Plan

### Step 1: Fix migration chain
**File:** `online-booking/backend/alembic/versions/sync_missing_columns.py`

Change `down_revision` from `'aaa7fcc30d47'` to `'f43f84fe3057'`.

This ensures the full chain is:
```
9a9c2edb119f → 08fbbef38349 → f43f84fe3057 → aaa7fcc30d47 → sync_missing_columns
```

### Step 2: Add migration for `cities.name_en`
Create new file: `online-booking/backend/alembic/versions/<hash>_add_cities_name_en.py`

- `down_revision = 'sync_missing_columns'`
- Add `name_en` column to `cities` table (nullable, server_default='')
- Idempotent: check if column exists before adding

### Step 3: Generate baseline migration
Run: `alembic revision --autogenerate -m "baseline: capture current schema"`

- Creates a new migration that captures ALL current tables/columns
- Becomes the new head of the migration chain
- After this, `alembic autogenerate` will work correctly for future changes

### Step 4: Make `alembic.ini` environment-aware
**File:** `online-booking/backend/alembic.ini`

Change:
```ini
sqlalchemy.url = postgresql+psycopg2://specialist:Postgres2024!Secure@localhost:5432/online_booking
```
To:
```ini
sqlalchemy.url = ${DATABASE_URL:sqlite+aiosqlite:///./online_booking.db}
```

Uses `${VAR:default}` syntax — Alembic reads the env var, falls back to default if not set.

### Step 5: Fix `deploy.yml` — export DATABASE_URL before migrations
**File:** `.github/workflows/deploy.yml`

Add `export DATABASE_URL` before running migrations:
```yaml
script: |
  cd /var/www/beauty-specialist
  git config --global --add safe.directory /var/www/beauty-specialist
  git pull origin main
  git reset --hard HEAD

  # Export DATABASE_URL for migrations and scripts
  export DATABASE_URL="${{ secrets.DATABASE_URL }}"

  # Write systemd service
  bash deploy_setup.sh

  # Backend
  cd online-booking/backend
  ...
```

Also update `deploy_setup.sh` to use `${DATABASE_URL}` env var instead of hardcoded URL.

### Step 6: Fix `create_superuser_sync.py` — use env var
**File:** `online-booking/backend/create_superuser_sync.py`

Change hardcoded URL to read from environment:
```python
DATABASE_URL = os.environ.get("DATABASE_URL", "postgresql+psycopg2://specialist:Postgres2024!Secure@localhost:5432/online_booking")
```
