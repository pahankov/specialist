# План переработки модуля авторизации/регистрации

## Контекст

Текущая реализация:
- **Backend:** FastAPI + SQLAlchemy (async) + PostgreSQL + JWT (python-jose) + bcrypt
- **Модели:** `Master` (мастера) и `Client` (клиенты) — раздельные таблицы, без географических полей
- **Аутентификация:** JWT в cookies, token rotation для мастеров, клиенты логинятся только по телефону (без пароля)
- **Роли:** Master (`is_admin=False`) и Superadmin (`is_admin=True`)
- **Проблема:** Нет городов/регионов, клиентская авторизация без пароля, раздельные таблицы пользователей

## Предлагаемая архитектура

### 1. Единая таблица пользователей (Unified User)

**Цель:** Одна таблица `users` вместо раздельных `masters` и `clients`.

#### 1.1 Новая модель `User`

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | Integer | PK |
| `email` | String(255), unique | Email (уникальный) |
| `phone` | String(20), unique | Телефон (уникальный) |
| `hashed_password` | String(255) | Хеш пароля (для master/admin) |
| `name` | String(100) | Отображаемое имя |
| `role` | Enum | `master`, `client`, `admin` |
| `city_id` | Integer, FK → City | Город (для master — обязательный, для client — опциональный) |
| `is_active` | Boolean | Активность аккаунта |
| `is_verified` | Boolean | Подтверждён ли email |
| `created_at` | DateTime | |
| `updated_at` | DateTime | |

#### 1.2 Связанные таблицы (сохраняются)

| Таблица | Описание |
|---------|----------|
| `master_profiles` | Специфичные для мастера данные: `user_id` (FK), `description`, `avatar_url`, `telegram_username`, `experience_years` |
| `client_profiles` | Специфичные для клиента данные: `user_id` (FK), `no_show_count`, `preferred_service_ids` (JSONB) |
| `refresh_tokens` | FK на `users.id` вместо `masters.id` |

#### 1.3 Migration strategy

```
0004_add_countries_and_cities → 0005_add_user_model → 0006_migrate_masters_to_users
→ 0007_migrate_clients_to_users → 0008_drop_old_tables
```

### 2. Многогородность и мультистранность

#### 2.1 Модели `Country` и `City`

| Модель | Поля |
|--------|------|
| `Country` | `id`, `code` (ISO 3166-1 alpha-2), `name_ru`, `name_en`, `phone_prefix`, `is_active` |
| `City` | `id`, `country_id` (FK), `name_ru`, `name_en`, `slug` (unique per country), `is_active` |

#### 2.2 Города России

**Подход:** Загрузить полный список городов через бесплатный API/дамп (например, [db-ip.com/city-ip-lookup-database](https://db-ip.com/db/download/datasets) или [GeoNames](http://www.geonames.org/)).

**Оптимизация:** Пагинация на уровне API (`GET /api/v1/cities?country_id=RU&page=1&page_size=100`), autocomplete для поиска (`GET /api/v1/cities?search=москва`).

#### 2.3 Seed-данные

- Страны: Россия (RU), Беларусь (BY), Казахстан (KZ), Узбекистан (UZ), Армения (AM), Азербайджан (AZ), Грузия (GE)
- Города: полный список России (~1100 городов с населением >1000) + основные города СНГ

### 3. SMS-аутентификация для клиентов

#### 3.1 OTP-код на телефон

| Шаг | Описание |
|-----|----------|
| 1 | Клиент вводит телефон → `POST /api/v1/auth/send-otp` → SMS с 6-значным кодом (TTL 5 мин) |
| 2 | Клиент вводит код → `POST /api/v1/auth/verify-otp` → JWT + refresh-token cookie |

#### 3.2 Таблица `otp_codes`

| Поле | Тип |
|------|-----|
| `id` | Integer, PK |
| `phone` | String(20) |
| `code_hash` | String(255) |
| `expires_at` | DateTime |
| `is_used` | Boolean |
| `created_at` | DateTime |

#### 3.3 Абстракция SMS-провайдера

```python
class SmsProvider(Protocol):
    async def send(self, phone: str, code: str) -> bool: ...
```

Реализации:
- `FakeSmsProvider` — логирует код в консоль (`logging.info(f"OTP for {phone}: {code}")`)
- `TwilioSmsProvider` — production (требует Account SID + Auth Token)
- `SmscRuSmsProvider` — production (требует login + password)

**На старте — только `FakeSmsProvider`.**

---

### 4. Безопасность

| Изменение | Описание |
|-----------|----------|
| **Access token → httponly** | Сейчас access_token не httponly — уязвимость XSS |
| **Rate limiting** | 5 попыток/мин на IP для login, 3 попытки/мин для OTP |
| **Password reset** | `POST /api/v1/auth/forgot-password` → email с токеном → `POST /api/v1/auth/reset-password` |
| **Email verification** | После регистрации мастера — подтверждение email |

## Верификация

### Как тестировать:

1. **Города:**
   - `GET /api/v1/countries` — список стран
   - `GET /api/v1/cities?country_id=RU&page=1&page_size=100` — пагинация
   - `GET /api/v1/cities?search=москва` — autocomplete
   - Регистрация мастера с `city_id` — мастер привязан к городу

2. **Unified User:**
   - Все старые endpoints работают (backwards compatibility)
   - JWT payload содержит `role` field
   - `require_master` и `require_client` работают через `get_current_user`

3. **SMS OTP:**
   - `POST /api/v1/auth/send-otp` — код в логах (fake mode)
   - `POST /api/v1/auth/verify-otp` — возвращает JWT + refresh cookie
   - Клиент получает refresh token

4. **Безопасность:**
   - Access token в httponly cookie
   - Rate limiting: 6-я попытка → 429

5. **Тесты:**
   - `pytest tests/test_cities.py` — зелёные
   - `pytest tests/test_users.py` — зелёные
   - `pytest tests/test_otp.py` — зелёные
   - `pytest tests/test_auth.py` — зелёные
   - `pytest tests/test_security.py` — зелёные
