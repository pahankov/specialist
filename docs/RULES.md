## ✏️ Правила создания/редактирования

### 1. Никакого дублирования

**Плохо:** Один и тот же чеклист в DEPLOY.md и README.md

**Хорошо:** Один источник правды, ссылки из других файлов

```markdown
# В DEPLOY.md
> Подробный чеклист деплоя

# В README.md
> Полный чеклист — [DEPLOY.md#чеклист](DEPLOY.md#чеклист)
```

### 2. Всегда актуальные пути

**Правило:** Перед коммитом проверь все относительные пути в документации.

```bash
# Проверка существования файлов, на которые есть ссылки
test -f DEPLOY.md && echo "OK" || echo "MISSING"
test -f DB.md && echo "OK" || echo "MISSING"
test -f LOCAL.md && echo "OK" || echo "MISSING"
```

### 3. Обновляй при изменении кода

**Правило:** Если меняешь код — ОБЯЗАТЕЛЬНО обновляй документацию.

| Изменил код | Нужно обновить |
|-------------|---------------|
| Новую таблицу БД | DB.md |
| Новую миграцию | DB.md + DEPLOY.md |
| Новый эндпоинт | README.md |
| Новый скрипт деплоя | DEPLOY.md |
| Новую переменную окружения | LOCAL.md + README.md |
| Новый тест | TESTING.md |

### 4. Пиши конкретно, не абстрактно

**Плохо:**
```markdown
# Нужно настроить БД
# Подключите базу данных
```

**Хорошо:**
```markdown
# База данных: PostgreSQL 16
# Имя БД: online_booking
# Пользователь: specialist
# Подключение:
DATABASE_URL=postgresql+psycopg2://specialist:PASSWORD@localhost:5432/online_booking
```

### 5. Используй таблицы для структурированных данных

**Плохо:**
```markdown
Пароль: REDACTED_DB_PASSWORD, пользователь: specialist, база: online_booking
```

**Хорошо:**
```markdown
| Параметр | Значение |
|----------|----------|
| User | specialist |
| Password | REDACTED_DB_PASSWORD |
| Database | online_booking |
```

### 6. Код должен быть рабочим

**Правило:** Все примеры команд и кода должны быть проверены перед коммитом.

```bash
# Плохо: команда не запускается
$env:PYTHONPATH='backend'  # ❌ Не работает в PowerShell

# Хорошо: проверенная команда
$env:PYTHONPATH='.'  # ✅ Работает из корня проекта
```

### 7. Не пиши "TODO" в документации

**Плохо:**
```markdown
# TODO: добавить секцию по миграциям
# FIXME: обновить после рефакторинга
```

**Хорошо:**
```markdown
# Миграции Alembic
# [Подробности в DB.md#миграции-alembic](DB.md#миграции-alembic)
```

### 8. История версий — только в README.md

**Правило:** Лог изменений хранится ТОЛЬКО в README.md. Не дублируй в других файлах.

```markdown
## 📚 История версий

### [1.5.0] — 2026-10-07
- DEPLOY.md: переписана с нуля, убраны дубликаты
- DB.md: добавлена полная документация БД
```

## 🔒 Правила безопасности

### 1. Никогда не коммить секреты

**Запрещено в git:**
- Пароли
- API ключи
- JWT secrets
- SSH пароли
- Токены

**Разрешено:**
- Плейсхолдеры: `<password>`, `<api-key>`, `<secret>`
- Ссылки на LOCAL.md

### 2. Все секреты — только в LOCAL.md

**Правило:** LOCAL.md — ЕДИНСТВЕННОЕ место для реальных секретов.

```markdown
# LOCAL.md — Локальные секреты и настройки

> ⚠️ ВАЖНО: НЕ должен попадать в git!
```

### 3. Проверка перед коммитом

```bash
# Проверка на утечку секретов
git diff --cached | Select-String -Pattern "password|secret|token|api_key|DADATA|TELEGRAM_BOT" -CaseSensitive

# Проверка всей истории
git log --all -p | Select-String -Pattern "REDACTED_" | Measure-Object | Select-Object -ExpandProperty Count
# Должно быть 0
```

### 4. Удаление секретов из истории

Если секреты попали в git — НЕМЕДЛЕННО:

```bash
# 1. Создай файл замен
echo "real-password=>REDACTED_PASSWORD" > secrets-to-remove.txt

# 2. Запусти filter-repo
git filter-repo --replace-text secrets-to-remove.txt --force

# 3. Удали файл с секретами
rm secrets-to-remove.txt

# 4. Очисти reflog
git reflog expire --expire=now --all
git gc --prune=now --aggressive

# 5. Проверь
git log --all -p | Select-String "real-password"
# Должно быть 0 совпадений
```

## 🚫 Анти-паттерны

### 1. "Создай файл, но не добавь в .gitignore"

**Ошибка:** LOCAL.md попадает в git

**Решение:**
```gitignore
# .gitignore
LOCAL.md
.env
.env.local
```

### 2. "Напиши документацию, но не проверь пути"

**Ошибка:** Ссылка на несуществующий файл

**Решение:**
```bash
# Перед коммитом
test -f DEPLOY.md && test -f DB.md && test -f LOCAL.md && echo "All docs OK"
```

### 3. "Обнови код, но не документацию"

**Ошибка:** Документация устарела

**Решение:**
```markdown
# Правило: код и документация обновляются вместе
# Если меняешь код — ОБЯЗАТЕЛЬНО обнови документацию
```

### 4. "Дублируй информацию в нескольких файлах"

**Ошибка:** Один и тот же чеклист в DEPLOY.md и README.md

**Решение:**
```markdown
# Один источник правды, ссылки из других файлов
# В DEPLOY.md: подробный чеклист
# В README.md: ссылка на DEPLOY.md
```

### 5. "Пушишь секреты в git"

**Ошибка:** Пароли в коммитах

**Решение:**
```bash
# Проверка перед push
git log --all -p | Select-String -Pattern "password|secret|token" -CaseSensitive
# Если есть совпадения — НЕ пушь!
```

## 📝 Примеры

### Правильное обновление документации

```bash
# 1. Изменил код (добавил новую таблицу БД)
# 2. Обновил DB.md
# 3. Проверил пути
test -f DB.md && echo "OK"
# 4. Проверил секреты
git diff --cached | Select-String "password|secret"
# 5. Закоммитил
git add DB.md
git commit -m "docs: add new table documentation"
```

### Правильное удаление секретов

```bash
# 1. Нашёл секреты в истории
git log --all -p | Select-String "real-password"

# 2. Создал файл замен
echo "real-password=>REDACTED_PASSWORD" > secrets-to-remove.txt

# 3. Удалил из истории
git filter-repo --replace-text secrets-to-remove.txt --force

# 4. Очистил reflog
git reflog expire --expire=now --all
git gc --prune=now --aggressive

# 5. Проверил
git log --all -p | Select-String "real-password"
# 0 совпадений — ОК!
```
