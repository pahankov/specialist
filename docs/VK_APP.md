# VK: приложение VK ID, вход и уведомления

> Документ описывает текущую интеграцию с VK: VK ID (OAuth 2.0 + PKCE),
> привязку профиля, сообщения от сообщества и требования к VK Mini App.
> Секреты в документе не хранятся — только имена переменных.

## 1. Что уже работает

| Возможность | Статус | Код |
|---|---|---|
| Вход и регистрация через VK ID | ✅ | `app/modules/vkauth/`, `VkIdWidget.tsx` |
| Виджет VK + Одноклассники + Mail одним блоком | ✅ | `@vkid/sdk`, `OAuthList` |
| Привязка VK к текущему аккаунту | ✅ | `link=true` в `/auth/vk/start` |
| Обратный редирект `/auth/vk/callback` | ✅ | `VkCallbackPage.tsx` |
| Уведомления в VK от имени сообщества | ✅ | `app/services/vk_notify.py` |
| VK Mini App (VK Bridge + launch params) | ❌ пока нет | план в §9 |

Новый аккаунт всегда создаётся с ролью CLIENT. Мастер входит в существующий
аккаунт и попадает в `/admin`; суперпользователь — в `/super`.

## 2. Архитектура входа

```
Браузер                         Backend                        VK ID
   │                               │                             │
   │ PKCE code_verifier (локально) │                             │
   │ POST /auth/vk/start           │                             │
   │ {code_challenge, link} ──────>│ подписывает state (HMAC)    │
   │<── authorize_url, state, ─────│                             │
   │    client_id, redirect_uri    │                             │
   │                               │                             │
   │ Config.init(state, verifier)  │                             │
   │ OAuthList widget ─────────────┼────────────────────────────>│
   │                               │                             │
   │ LOGIN_SUCCESS(code, device_id)│                             │
   │ POST /auth/vk/verify ────────>│ exchange_code ─────────────>│
   │ {code, device_id, state,      │<── access/refresh/id token ─│
   │  code_verifier, consent}      │ user_info ─────────────────>│
   │<── JWT + cookies / challenge ─│ создаёт/привязывает аккаунт │
```

Ключевые свойства:

- **PKCE обязателен.** `code_verifier` генерируется в браузере, в VK уходит
  только `code_challenge` (S256); verifier предъявляется при обмене кода.
- **Обмен кода — на сервере.** Токены VK не попадают в браузер; backend
  хранит `VK_SERVICE_TOKEN`.
- **`state` подписан нами.** HMAC + TTL 10 минут; чужой/просроченный state
  отклоняется до обращения к VK.
- **Согласие 152-ФЗ.** Новый аккаунт без согласия получает `challenge`, а не
  сессию; `ConsentScreen` вызывает `/auth/consent/complete`.

## 3. Настройка приложения VK ID

1. Создайте приложение в кабинете VK ID (`id.vk.ru`).
2. Укажите доверенный Redirect URI **точно** как на сайте:
   - прод: `https://beauty-specialist.ru/auth/vk/callback`
   - локально: `http://localhost:3000/auth/vk/callback`
3. Скопируйте «ID приложения» в `VK_CLIENT_ID`. Это строка (в новых VK ID —
   hex), её нельзя приводить к числу.
4. Скопируйте «Сервисный ключ доступа» в `VK_SERVICE_TOKEN`. Это именно
   сервисный ключ, а не «Защищённый ключ» классического VK API: backend
   отправляет его как `service_token` и `client_secret` при обмене кода.
5. При необходимости включите доступ к email/телефону в кабинете приложения и
   перечислите scope в `VK_SCOPE` (через пробел). Пусто — набор VK по умолчанию
   (`vkid.personal_info`).
6. Заполните серверный `online-booking/backend/.env` и перезапустите backend.

```dotenv
VK_CLIENT_ID=<ID приложения>
VK_SERVICE_TOKEN=<Сервисный ключ доступа>
VK_REDIRECT_URI=https://beauty-specialist.ru/auth/vk/callback
VK_SCOPE=

# Отдельно — для сообщений от сообщества (не путать с VK_SERVICE_TOKEN):
VK_NOTIFY_TOKEN=<токен сообщества с правом messages>
VK_API_VERSION=5.199
```

### Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `VK_CLIENT_ID` | да | ID приложения VK ID |
| `VK_SERVICE_TOKEN` | для confidential-приложений | Сервисный ключ для обмена кода |
| `VK_REDIRECT_URI` | да | Зарегистрированный redirect на фронтенд |
| `VK_SCOPE` | нет | Дополнительные права через пробел |
| `VK_NOTIFY_TOKEN` | для уведомлений | Токен сообщества с `messages` |
| `VK_API_VERSION` | нет | Версия VK API, по умолчанию `5.199` |

`vk_enabled` включается только при непустых `VK_CLIENT_ID` и
`VK_REDIRECT_URI`. Если чего-то не хватает, `/auth/vk/start` отвечает `503`,
а виджет на сайте показывает «Вход через VK не настроен».

## 4. API

| Метод | Путь | Тело / ответ |
|---|---|---|
| `POST` | `/api/v1/auth/vk/start` | `{code_challenge, link?}` → `{authorize_url, state, client_id, redirect_uri}`; 10/min |
| `POST` | `/api/v1/auth/vk/verify` | `{code, device_id, state, code_verifier, consent}` → JWT/cookies или `{challenge}`; 10/min |

`link=true` доступен только авторизованному пользователю: подписанный `state`
несёт `user_id`, и профиль привязывается к текущему аккаунту, а не создаёт
новый. При отмене привязки фронт возвращает пользователя в профиль.

Типичные ошибки:

| Код | Причина |
|---|---|
| `400` | неверный/просроченный `state`, отклонённый обмен кода, VK не вернул `user_id` |
| `401` | `link=true` без активной сессии |
| `503` | VK ID не настроен |
| `challenge` в ответе | новый аккаунт без согласия 152-ФЗ — требуется `ConsentScreen` |

## 5. Виджет и резервный редирект

- Основной путь — официальный `@vkid/sdk` (`OAuthList`) с кнопками VK,
  Одноклассники и Mail. Виджет рисуется прямо в модалке входа; на форме
  регистрации — только после отметки согласия.
- `Config.init` получает наш `state` и `code_verifier`; после успеха SDK
  отдаёт `code` + `device_id`, которые уходят в `/auth/vk/verify`.
- Если виджет недоступен, `LoginModal` умеет начать обычный редирект через
  `authorize_url`. Страница `/auth/vk/callback` забирает `code`, `device_id`,
  `state`, достаёт verifier из `sessionStorage` и завершает тот же
  серверный обмен.
- В callback-режиме проверяется совпадение сохранённого `state` с возвращённым.

## 6. Привязка VK к аккаунту

Профиль → «Вход и привязки» → «Привязать VK»:

1. Фронт вызывает `/auth/vk/start` с `link=true` (нужна активная сессия).
2. Backend кладёт `user_id` в подписанный `state`.
3. После успеха вызывается `bind_social_login`, а не создание нового
   пользователя; `users.vk_user_id` заполняется.
4. VK-почта считается подтверждённой провайдером и попадает в контакты.
5. Повторная привязка другого VK к тому же аккаунту заменяет привязку;
   чужой VK, уже привязанный к другому пользователю, отклоняется.

## 7. Уведомления в VK

Вход через VK ID **не даёт права писать пользователю**. Для сообщений нужно:

1. Создать сообщество VK.
2. Получить токен сообщества с правом `messages`
   («Управление → Работа с API»).
3. Записать его в `VK_NOTIFY_TOKEN` (это не `VK_SERVICE_TOKEN`).
4. Пользователь должен разрешить сообщения от сообщества; иначе VK вернёт
   ошибку доставки.

Как работает доставка:

- Канал доступен при `users.vk_user_id` + `VK_NOTIFY_TOKEN`.
- `notification_settings.choose_channel` учитывает `vk_enabled` пользователя,
  последний способ входа и порядок `MAX → VK → email`.
- `vk_notify.send_vk_message` вызывает `messages.send` с `random_id`,
  обрезает текст до 4000 символов и логирует ошибки VK без токена.
- Результат фиксируется в `notifications.external_channel` /
  `external_error`; неудачная доставка не блокирует остальные уведомления.

Частые ошибки VK:

| Код VK | Значение | Что делать |
|---|---|---|
| `901` | пользователь запретил сообщения | Попросить разрешить сообщения сообщества |
| `902` | пользователь не разрешил сообщения | То же |
| `7` | нет прав | Проверить право `messages` у токена |
| `5` | неверный токен | Перевыпустить токен сообщества |

## 8. Диагностика входа

| Симптом | Причина / решение |
|---|---|
| «Вход через VK не настроен» | Пустые `VK_CLIENT_ID` / `VK_REDIRECT_URI` или backend не перезапущен |
| `redirect_uri` mismatch | URL в кабинете VK ID не совпадает с `VK_REDIRECT_URI` символ в символ |
| «Неверная или просроченная сессия входа» | `state` старше 10 минут или `SECRET_KEY` изменился между стартом и callback |
| Виджет не рисуется | Проверьте `@vkid/sdk`, домен в trusted redirect и консоль браузера |
| `VK ID ... error` в логах | Проверьте `VK_SERVICE_TOKEN` (сервисный ключ, не защищённый) |
| Уведомления не приходят | `VK_NOTIFY_TOKEN` пуст, нет права `messages` или пользователь запретил сообщения |

Проверочный чек-лист после настройки:

- [ ] `/auth/vk/start` возвращает `authorize_url`, а не `503`.
- [ ] Вход новым аккаунтом создаёт CLIENT и требует согласие 152-ФЗ.
- [ ] Повторный вход тем же VK не создаёт дубль (`vk_user_id` уникален).
- [ ] «Привязать VK» в профиле возвращает в профиль, а не в кабинет.
- [ ] Мастер входит через VK и попадает в `/admin`.
- [ ] Тестовое уведомление приходит в VK при разрешённых сообщениях.

## 9. VK Mini App (план)

Сейчас приложение работает как обычный сайт; VK Mini App (VK Bridge,
`launch_params`) в кодовой базе отсутствует. Если понадобится открывать
запись внутри VK:

1. **Публикация.** Создать Mini App в кабинете VK, указать URL
   `https://beauty-specialist.ru`; VK откроет существующий SPA в iframe/webview.
2. **VK Bridge.** Подключить `@vkontakte/vk-bridge`, получить
   `VKWebAppGetLaunchParams` (подписанные `vk_user_id`, `vk_app_id` и др.).
3. **Проверка на сервере.** Новый endpoint (например,
   `POST /api/v1/auth/vk/miniapp`) должен проверять подпись launch params
   секретом приложения и срок жизни, затем находить/создавать пользователя по
   `vk_user_id`. Данные из клиента без проверки подписи не принимаются.
4. **Сессия.** Выдать те же JWT + cookies, что и в VK ID; фронт переходит в
   `/cabinet`.
5. **Ограничения webview.** Проверить safe-area, высоту, нативные date-picker,
   загрузку файлов и внешние редиректы; OAuth-переходы и платежи открывать
   через `VKWebAppOpenURL`/системный браузер.
6. **Безопасность.** Не логировать launch params; отклонять просроченные
   подписи; не доверять `vk_user_id` из URL; не отключать PKCE/`state` для
   обычного веб-входа.

До реализации Mini App кнопка «Открыть в VK» должна вести на обычный сайт.
